# crank-pilot's JS dev tools are pinned at the repo root, not in the plugin

Claude Code runs a package install in a plugin's cache copy whenever the plugin root holds a `package.json` and a lockfile it supports, so a manifest inside `plugins/crank-pilot/` would make every install download the linters, type checker and test DOM, which the command never uses at runtime. The JS dev tools are therefore pinned in the root `package.json` under pnpm. Their config files live in the plugin (`tsconfig.json`, `.oxlintrc.json`, `.prettierrc.json`, `.prettierignore`) except knip's and fallow's: knip runs only from a directory holding a `package.json`, and crank-health runs `fallow dead-code` from the repo root, so `knip.json` and `.fallowrc.json` sit at the repo root with paths scoped to `plugins/crank-pilot/`. The Python dev tools are pinned in the plugin's own `pyproject.toml` and `uv.lock`; Claude Code installs no Python dependencies for a plugin. A plugin-local manifest behind a lockfile Claude Code skips was rejected because it rests on an exclusion the docs do not promise.
